# 캠프 젤리 · Camp Jelly (fallguys)

> 최대 30명이 초대 링크로 모여 달리는 독립 제작 3D 장애물 파티 게임입니다. 폴가이즈에서 착안한 레이스이며, 캐릭터와 화면은 이 프로젝트에서 직접 만들었습니다.

**[공개 게임 바로가기](https://camp-jelly.43-200-53-244.nip.io/)** · [GitHub 저장소](https://github.com/kimmokdong/fallguys)

## 실행 방법

Node.js 22 이상이 설치된 PC에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm install
npm start
```

[게임 열기](http://localhost:3000) → **방 만들기** → 이름 입력 → 초대 링크 복사 → 친구 입장·준비 완료 → 방장이 시작.

- 친구는 초대 링크의 이름 입력창에서 이름만 입력하면 대기실에 들어옵니다.
- 방장은 맵 16개 중 모드에 맞는 맵 또는 랜덤, 캐릭터 직접 선택 또는 랜덤 배정, 제한 시간 1~5분을 선택합니다.
- 경기 모드는 **탈락전(기본) / 단판 / 누적 점수전** 중 선택합니다. 점수전은 **3·5·7판**이며, 랜덤 맵을 선택하면 한 경기 안에서 맵이 중복되지 않습니다.
- 랜덤 배정은 한 방 안에서 30종을 중복 없이 배정합니다. 색상 20종은 항상 플레이어가 선택할 수 있습니다.
- 참가자는 캐릭터를 고른 뒤 **준비 완료**를 누릅니다. 방장은 시작 버튼으로 준비를 확인하며, 모두 연결·준비되어야 시작됩니다. 경기 설정 변경 시 모두의 준비가, 외형 변경 시 본인의 준비가 해제됩니다. 재접속 후에도 다시 준비합니다.
- 캐릭터 선택창은 이모지 대신 **실제 3D 모델 30종과 선택 색상**을 보여줍니다.
- 혼자 입장해 연습할 수도 있습니다. 경기 중 새 참가자는 대기실에 돌아올 때까지 입장할 수 없습니다.
- 방장이 나가면 다른 참가자에게 방장 권한이 넘어갑니다. 새로고침과 짧은 연결 끊김은 20초 이내 같은 자리에 복구됩니다.

## 디자인

**화면 크기 대응**: 홈·대기실·입장·캐릭터 선택·경기 설정·결과 화면은 브라우저의 실제 높이에 맞춰 여백과 사진 크기를 조절합니다. 크롬북·태블릿(가로 600px 이상)에서도 PC의 좌우 배치를 유지하고, 준비·시작·선택 완료 버튼은 화면 안에 남깁니다. 긴 참가자·캐릭터·맵·설정 목록만 내부 스크롤합니다. 1920×900, 1366×650, 1024×600, 768×1024, 600×900 및 390×844에서 확인했으며, 가로 800×480에서도 대기실 준비 버튼을 바로 누를 수 있습니다. 세로 휴대폰에서는 좁은 폭에 맞춰 위아래로 배치합니다.

**현재 게임에 적용한 화면**: 간결한 캠프 홈·이름 입력·참가자 중심 대기실·캐릭터 선택과 C 스포트라이트 결과 화면을 연결했습니다. 대기실의 사진과 이름은 크게 유지하고 참가자가 늘면 목록 안에서만 스크롤합니다. 방장은 참가자 카드를 눌러 접속 중이거나 연결이 끊긴 참가자를 강퇴할 수 있습니다. 강퇴한 자리의 재접속 토큰은 폐기됩니다. 강퇴는 해당 자리를 제거하는 기능으로, 새 초대 입장을 영구 차단하는 기능은 아닙니다.

캐릭터 선택 메뉴를 열면 **캐릭터 고르는 중**, 닫으면 **대기 중**, 준비 버튼을 누르면 **준비 완료**로 서버에서 구분합니다. 결과 사진은 높은 순위를 위쪽에 고정하고, 미완주·낮은 순위부터 한 명씩 크게 공개해 1위를 마지막에 보여줍니다. 단판 기록과 점수전 라운드 점수·최종 누적 점수를 모두 지원합니다. FHD에서 12명은 최대 4열, 26·30명은 6열×5줄이며 비어 있는 자리는 남깁니다. 가로 600px 이상의 크롬북·태블릿에서는 사진과 여백을 조절해 좌우 배치와 진행 버튼을 유지합니다. 세로 휴대폰은 위아래 배치와 내부 스크롤을 사용합니다.

**결과 화면 비교 시안**: [시안 3종 열기](http://localhost:3000/result-review.html?design=spotlight&count=26). A 숲속 시상대, B 정상으로 가는 길, C 오늘의 주인공에서 12명·26명·30명 카드 배치를 비교합니다. 선택한 C 시안은 1위부터 사진을 위쪽에 배치하고 공개는 아래쪽 꼴찌부터 1위까지 진행합니다. FHD에서 12명은 4열×3줄, 26명·30명은 같은 카드 크기의 6열×5줄로 스크롤 없이 표시하며, 26명의 마지막 줄은 두 장만 채웁니다. 작은 창에서는 반응형 배치에 따라 열 수와 스크롤 여부가 달라집니다. 기존 결과 정렬과 공개 간격을 재사용하며 다시 보기·일시정지·완성 화면을 제공합니다. 실제 방에 접속하지 않는 검토용 예시입니다.

**승인된 심플 웹 시안 기록**: [시안 열기](http://localhost:3000/simple-review.html). 참고 이미지의 넓은 화면과 간결한 버튼 배치를 반영하고, 기존 B 콘셉트의 숲 초록·세이지·흙빛 베이지를 유지합니다. 예시 데이터로 동작하는 검토용 화면을 별도 보존하며, 승인한 배치와 기능은 현재 게임에도 연결했습니다. 기존 모바일 시안 주소는 이 시안으로 이동합니다.

사용자가 선택한 **B 캠프 젤리**를 실제 홈·대기실·입장/캐릭터 모달·HUD·결과 화면과 모든 맵에 적용했습니다. 숲색·흙빛·목재 단면·나무 장식, 낮춘 조명과 노출, 무광의 흰 캐릭터와 진한 발판 경계선을 사용합니다. 캐릭터 색상은 20가지로 확장했습니다.

[디자인 비교실](http://localhost:3000/design-review.html?theme=forest)은 별도 참고 데모로 유지합니다. 최신 화면은 새로고침하면 반영됩니다. 서버 규칙이 함께 바뀌는 업데이트는 서버 재시작과 새 방 생성이 필요합니다.

## 조작

| 기기 | 이동 | 점프 | 슬라이딩 |
| --- | --- | --- | --- |
| PC | WASD 또는 방향키 | Space | E |
| 모바일·태블릿 | 왼쪽 가상 조이스틱 | 오른쪽 점프 | 오른쪽 슬라이딩 |

레이스에서 떨어지면 마지막으로 통과한 번호 깃발에서 다시 시작합니다. 생존에서 떨어지면 탈락하고 관전합니다. 점프는 키를 놓았다 다시 눌러야 합니다. 모든 캐릭터의 능력치는 같습니다. 플레이어끼리 몸으로 길을 막고 밀 수 있고, 달려온 속도가 빠르거나 다이빙하면 충격이 더 큽니다. 충분히 높이 점프하면 머리 위로 지나갈 수 있으며, 체크포인트 복귀 직후에는 잠깐 몸싸움 보호를 받습니다.

- **점프 보정**: 발판을 벗어난 뒤 약 100ms까지 점프할 수 있고, 착지 120ms 전의 입력도 착지 후 실행합니다. 짧은 키·터치 입력이 서버 틱 사이에서 사라지지 않도록 보관하며 이단 점프와 누르고 있기 자동 점프는 허용하지 않습니다.
- **효과음**: 점프·착지·슬라이딩·충돌·체크포인트·완주·탈락·출발 소리를 Web Audio로 합성합니다. 첫 클릭/키 입력, 경기 시작과 탭 복귀에서 오디오 연결을 복구합니다. 실제 오디오 연결 상태를 소리 버튼에 표시하고, 켤 때 확인음을 재생합니다. 게임 방법의 음량 슬라이더와 소리 확인 버튼을 사용할 수 있으며 음량·켜짐 상태를 저장합니다.
- **배경음악**: 청취 비교 후 승인한 48kbps MP3 4곡을 사용하고 곡 사이 음량을 맞췄습니다. 이전 96kbps 약 8.38MB → 현재 약 4.19MB(곡당 0.95~1.13MB). 실제 경기 시작부터 무작위 순서로 재생하고 네 곡을 모두 들으면 다시 섞습니다. 결과·대기실·다른 탭·음소거에서는 일시정지하고 돌아오면 이어 듣습니다. 기존 소리 버튼과 음량 조절을 함께 사용합니다.
- **음원 전송 절약**: 홈·대기실에서는 음원을 요청하지 않고 카운트다운에서 재생할 한 곡만 준비합니다. 다음 곡은 현재 곡이 끝날 때 받습니다. `public/music/`의 내용 해시 파일명과 1년 브라우저 캐시·ETag 재검증을 사용하므로, 같은 브라우저에 캐시가 남아 있으면 다음 접속에서도 재사용합니다. 압축을 푼 오디오는 현재 곡 하나만 메모리에 보관합니다. 곡을 교체할 때는 새 내용 해시의 파일명을 만들고 `public/music.js` 목록을 갱신합니다. 원본 MP3는 프로젝트 루트의 작업용 파일이며 배포 웹 경로로 노출하지 않습니다.
- **코스 안내**: 출발 전 3초간 코스를 살펴보고 3초 카운트다운 후 출발합니다. 동작 줄이기 설정에서는 안내 카메라를 고정합니다.
- **발판 경고**: 사라지기 전 1초 동안 주황색 안내판과 줄어드는 막대가 나타납니다. 경고와 실제 사라짐은 같은 시간 계산을 사용합니다.
- **이름표**: 짙은 배경과 굵고 밝은 글씨로 확대했습니다. 내 이름과 관전 대상은 더 크게 표시하고, 너무 먼 상대의 이름은 숨깁니다.

## 경기 모드와 결과 발표

- **단판**: 레이스 12개 또는 생존 6개 중 맵을 고릅니다. 레이스는 완주 시간, 생존은 버틴 시간으로 순위를 정하며 시간까지 남은 참가자는 공동 생존입니다.
- **탈락전**: 레이스와 생존을 번갈아 진행합니다. 레이스는 출발 인원의 절반(홀수는 올림)이 통과하며, 슬롯이 채워지거나 시간이 끝나면 종료합니다. 같은 순간의 경계 순위는 함께 통과합니다. 생존은 목표 인원까지 줄거나 제한 시간이 되면 종료하고 남아 있는 참가자는 모두 통과합니다. 생존을 시작한 첫 3초는 이동할 시간을 줍니다.
- **결승**: 남은 인원이 5명 이하이면 결승입니다. 레이스는 가장 먼저 완주한 참가자, 생존은 마지막 생존자가 우승합니다. 결승 동률은 남은 참가자끼리 레이스 재결승을 치릅니다. 전원 실패는 우승자 없이 종료합니다. 라운드 수는 고정하지 않습니다.
- **탈락 이후**: 다음 라운드에는 캐릭터·충돌 판정을 생성하지 않고 관전만 합니다. 재접속해도 탈락은 유지되며, 탈락한 방장도 다음 라운드를 시작할 수 있습니다. 대기실로 복귀하면 모두 참가 상태로 초기화합니다.
- **완주 후 관전**: 달리는 친구를 자동으로 따라갑니다. 이름 선택·이전/다음·내 캐릭터 보기로 전환하며, 대상이 완주하거나 연결이 끊기면 다음 참가자를 보여줍니다.
- **누적 점수전**: 방장이 선택한 3·5·7판의 점수를 합산합니다. 한 판의 참가 인원이 N명이면 기본점수는 **N − 순위 + 1**이며, **1·2·3위는 N의 30%·15%·10%를 반올림해 추가**합니다. N은 출발 인원으로 미완주·중도 퇴장자도 포함합니다. 미완주는 0점이며 마지막 판에도 추가 배율은 없습니다. 예를 들어 26명 경기의 1~4위는 34·29·27·23점, 30명 경기의 1위는 39점, 30위는 1점입니다. 최종 동점은 공동 순위입니다.
- 각 판이 끝나면 방장이 **다음 라운드 시작**을 누릅니다. 마지막 판 뒤에는 누적 점수로 최종 순위를 공개합니다. 경기 중 참가자가 떠나도 이미 얻은 점수는 최종 결과에 남습니다.
- **결과 카드**: 실제 게임 캐릭터와 색상을 촬영한 정사각형 사진·이름 카드를 격자로 배열합니다. 미완주와 낮은 순위부터 한 장씩 뒤집히고 1위를 마지막에 공개합니다. 점수전에서는 누적 총점을 큰 글씨로, 이번 판 획득 점수를 그 아래에 표시하며 마지막에는 최종 총점을 표시합니다. 30명에서도 점수 표시는 숨기지 않습니다. 탈락전은 통과·탈락·우승 상태를, 단판은 완주 시간 또는 생존 기록을 보여줍니다.
- **모두 공개**로 연출을 건너뛸 수 있습니다. 시스템의 동작 줄이기 설정도 따릅니다.

## 16개의 코스

공통으로 붙이던 마지막 직선 구간을 없앴습니다. 번호 깃발을 순서대로 지나야 완주할 수 있으며 순위는 동선 진행도로 판정합니다. 뒤로 돌아오는 길이나 입체 경사로에서도 같은 규칙을 사용합니다. 다음 깃발 표시와 코스 지도로 방향을 안내하고, 조작 방향이 바뀌지 않도록 경기 카메라 방향을 유지합니다.

| 빙글빙글 시티 | 둘 다 | 레이스는 회전 원판 순환 코스, 생존은 회전 바닥과 회전봉 광장 |

- 동점자는 먼저 추첨하고 같은 줄의 좌우 자리도 섞습니다. 생존 라운드를 함께 통과한 참가자는 공동 순위이므로 다음 레이스 자리는 추첨합니다. 경기 명단·방장·기록 순서는 그대로 두고 서버가 각 참가자의 출발 슬롯만 결정합니다.
- 자동 테스트 41개 통과. 1~30명 중복 없는 슬롯, 26명 부분 줄, 누적 점수·직전 순위·동점, 탈락자 제외와 실제 WebSocket 다음 라운드의 앞줄 배정을 검증했습니다.

## 전송량 최적화 (2026-09-14)

- 게임 화면에 필요한 값만 바이너리로 전달합니다. 위치는 전송할 때만 소수 두 자리로 줄이고, 서버의 이동·충돌·순위 계산은 원래 정밀도를 유지합니다. 30명 전체 상태는 발판 변경이 없을 때 1,156바이트입니다.
- 바뀐 캐릭터와 발판만 보내며, 내 캐릭터와 가까운 상대는 기존 최대 15Hz, 먼 상대는 약 3Hz로 갱신합니다. 완주·탈락·낙하 복귀는 거리 제한을 건너뜁니다. 숨긴 탭은 빈도를 낮추고, 관전 대상 변경·탭 복귀·재접속·라운드 전환과 2초마다 전체 상태를 맞춥니다.
- 같은 입력은 250ms마다 연결 유지용으로만 보내고, 바뀐 이동·점프·슬라이딩 입력은 기존 주기로 전달합니다. 밀린 상태 전송은 건너뛰고 전체 동기화로 복구합니다. 기존 JSON 클라이언트도 연결되지만 절약 효과를 받으려면 새로고침해야 합니다.
- HTML·JavaScript·CSS는 Brotli/gzip으로 압축하고 파일별 ETag로 재검증합니다. 파일이 같으면 304로 본문 재전송을 피하면서, 변경된 코드는 즉시 새로 받습니다. 압축 결과를 재사용하므로 동시 입장마다 다시 압축하지 않습니다.
- 48kbps 음원은 새 내용 해시 주소와 1년 캐시를 사용합니다. 이미 열린 이전 클라이언트의 재생을 위해 이전 음원 주소도 보존하지만, 새 음악 목록은 48kbps 네 곡만 요청합니다.

### 측정 결과

로컬 서버에 30개 WebSocket 클라이언트를 연결하고 젤리 가든에서 같은 이동·점프·슬라이딩 패턴을 20초씩 실행했습니다. 전체 수신량과 WebSocket 프레임 헤더를 합산했으며, 초기 화면·음원 다운로드와 TLS/TCP 비용은 제외했습니다.

| 비교 | 기존 JSON 전송 | 새 바이너리·변경분 전송 |
| --- | ---: | ---: |
| 30명 · 약 20초 실측 | 110.21MB | 7.65MB |
| 같은 부하를 3분으로 환산 | 991MB | 69MB |

같은 조건에서 약 **93.1% 감소**했습니다. 측정 PC의 실제 상태 전송은 양쪽 모두 약 11Hz였으며, 서버의 목표 주기는 15Hz입니다. 3분 수치는 20초 결과의 환산값으로 Render 청구량 또는 실제 3분 경기 실측이 아닙니다. 맵·참가자 간 거리·완주 시간·브라우저 캐시에 따라 달라집니다. 네 곡을 처음 모두 받으면 30명 합계 약 126MB가 별도로 필요합니다.

- 자동 테스트 47개 통과: 기존 30인 입장·충돌·점수전·탈락전·재접속을 새 통신 방식으로 검증했습니다. 변경분 유지·전체 복구·거리 제한·발판 삭제·잘못된 패킷·슬롯 재사용·이전 클라이언트 호환·관전 권한·압축/304/HEAD/음원 구간 요청을 추가 검증했습니다.
- 실제 브라우저에서 새 방식으로 30명 대기실 → 경기 이동·점프 → 30명 결과 → 15명 다음 생존 라운드 전환과 브라우저 오류 0건을 확인했습니다. 실제 기기 30대의 장시간 플레이는 별도 확인 대상입니다.

## AWS 운영 (최신 게임 배포: 2026-09-22)

접속 주소: https://camp-jelly.43-200-53-244.nip.io/

- 서울 리전 `ap-northeast-2a`, Lightsail `camp-jelly` 1대: Ubuntu 24.04 LTS, 2 vCPU, 1GB RAM, SSD 40GB, 월 7달러, 월 2TB 송수신량.
- 고정 IPv4 `43.200.53.244`, 리소스 이름 `camp-jelly-ip`. 고정 IP는 서버에 연결되어 있습니다. 무료 nip.io 주소를 사용하므로 주소 해석은 해당 외부 서비스에 의존합니다. Render의 onrender.com 주소는 이전할 수 없습니다.
- 무료 계정 플랜 유지. 계정 콘솔에서 100달러 크레딧과 Lightsail 적용, 크레딧 만료일 **2027-09-21**을 확인했습니다. 무료 계정 플랜 자체의 종료일 **2027-03-21**과 다릅니다. 계속 운영하려면 무료 플랜 종료 전에 계정 전환 여부를 검토해야 합니다. 이번 작업에서 유료 계정 전환은 하지 않았습니다.
- 기본 월 7달러는 모든 비용의 상한이 아닙니다. 세금·추가 서비스·전송량 초과는 별도입니다. 여러 프로젝트는 메모리·CPU·전송량을 공유하며, 현재 이전한 프로젝트는 캠프 젤리 한 개입니다.

### 운영 구성

`/opt/camp-jelly`에서 `compose.yaml`로 게임 서버 1개와 Caddy HTTPS 프록시를 실행합니다. 게임 포트 3000은 외부에 게시하지 않고 80/443만 전체 공개합니다. SSH는 Lightsail 브라우저 접속으로 제한했으며 배포에 사용한 CloudShell IP 허용은 제거했습니다. SSH 암호 접속은 비활성화되어 있습니다. 임시 SSH 인증서는 CloudShell에서만 사용하고 작업 종료 시 삭제합니다. 서버에는 GitHub 토큰이나 AWS 영구 액세스 키를 저장하지 않았습니다.

Caddy 인증서는 Docker 볼륨에 보존되며 두 서비스는 재부팅 후 자동 시작합니다. 로그 보관 크기를 제한합니다. 48kbps 음원·바이너리 통신·정적 파일 압축과 캐시를 유지합니다. 게임 소스 배포 기준은 `b3f6ced`(2026-09-22)입니다. 이번 업데이트는 기존 음원을 제외한 158KB의 코드 묶음 중 변경한 게임 파일·테스트만 추출했습니다. 운영 중인 compose/Caddy 설정을 보존하고 게임 컨테이너만 재시작했으며 이전 소스와 이미지를 서버에 보관했습니다.

### 검증

- 로컬과 실제 AWS 컨테이너에서 자동 테스트 **54개 통과**. 공개 서버의 수정된 scene·courses 파일이 최신 코드와 일치함을 확인했습니다.
- 2026-09-22 공개 서버에서 30명 입장·경기 시작·점프·새 쿠션 반동 수신을 확인하고 테스트 방을 정리했습니다. 배포용 PC·CloudShell의 임시 SSH 허용도 모두 제거했습니다.
- 실제 AWS HTTPS/WSS에서 30명 동시 입장·30종 랜덤 캐릭터·31번째 입장 거부·준비 확인·경기 시작·점프·모든 참가자의 상태 수신 통과. 테스트 방은 퇴장 처리했습니다. 테스트 PC에서 WebSocket ping 한 번은 8ms였으며 다른 기기의 지연을 보장하는 값은 아닙니다.
- HTTPS 200, JavaScript Brotli 압축, ETag 304, 음원 Range 206/128바이트 및 1년 캐시 확인. Chrome 홈 화면과 3D 캐릭터 표시 정상, 확인 시 브라우저 오류·경고 없음.
- 테스트 방 정리 후 컨테이너 메모리: 게임 약 47MiB, HTTPS 약 39MiB. 전체 서버 가용 메모리 약 456MiB. 이는 유휴 시점의 측정이며 30대 실제 기기의 장시간 성능 검증은 별도입니다.

### 업데이트와 복구

**GitHub push만으로 AWS가 자동 배포되지는 않습니다.** 현재는 검증한 코드를 전달한 뒤 아래 명령으로 반영합니다. 서버 재시작 때 진행 중인 방과 결과는 초기화되므로 수업 외 시간에 배포합니다. 기존 Render 리소스는 삭제하지 않았습니다.

1. 로컬에서 `npm test`를 통과한 커밋을 `git archive --format=tar.gz --output=output/camp-jelly-aws.tar.gz HEAD`로 내보냅니다. 원본 음원·비밀 파일·node_modules는 포함하지 않습니다.
2. AWS CloudShell에 업로드하고 Lightsail 임시 SSH 인증과 해당 CloudShell IPv4만 허용하여 서버로 전달합니다. AWS가 제공한 호스트 키를 검증하며 인증서 내용은 출력하지 않습니다. 배포 후 임시 IP 허용을 제거합니다.
3. `/opt/camp-jelly`에 압축을 풀고 기존 `.env`의 `CAMP_DOMAIN=camp-jelly.43-200-53-244.nip.io`를 유지합니다.

~~~sh
cd /opt/camp-jelly
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=50
~~~

신규 서버 설치는 `lightsail-bootstrap.sh`를 사용합니다. Lightsail Launch script는 앞에 자체 `/bin/sh` 초기화 코드를 붙이므로 POSIX 문법과 LF 줄바꿈을 유지해야 합니다. `.gitattributes`에서 셸 파일의 LF를 고정했습니다. Dockerfile에는 서버가 사용하는 `http-assets.js`도 포함합니다.

방·경기는 메모리에 있으므로 게임 프로세스를 여러 개로 복제하지 않습니다. 과금 알림은 자동 과금 차단 장치가 아닙니다.
