# 캠프 젤리 · Camp Jelly (fallguys)

> 최대 30명이 초대 링크로 모여 달리는 독립 제작 3D 장애물 파티 게임입니다. 폴가이즈에서 착안한 레이스이며, 캐릭터와 화면은 이 프로젝트에서 직접 만들었습니다.

**[공개 게임 바로가기](https://camp-jelly.onrender.com/)** · [GitHub 저장소](https://github.com/kimmokdong/fallguys)

## 실행 방법

Node.js 22 이상이 설치된 PC에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm install
npm start
```

[게임 열기](http://localhost:3000) → **방 만들기** → 이름 입력 → 초대 링크 복사 → 친구 입장·준비 완료 → 방장이 시작.

- 친구는 초대 링크의 이름 입력창에서 이름만 입력하면 대기실에 들어옵니다.
- 방장은 맵 12개 중 하나 또는 랜덤, 캐릭터 직접 선택 또는 랜덤 배정, 제한 시간 2~5분을 선택합니다.
- 경기 모드는 **단판 레이스 / 누적 점수전** 중 선택합니다. 점수전은 **3·5·7판**이며, 랜덤 맵을 선택하면 한 경기 안에서 맵이 중복되지 않습니다.
- 랜덤 배정은 한 방 안에서 30종을 중복 없이 배정합니다. 색상 8종은 항상 플레이어가 선택할 수 있습니다.
- 참가자는 캐릭터를 고른 뒤 **준비 완료**를 누릅니다. 방장은 시작 버튼으로 준비를 확인하며, 모두 연결·준비되어야 시작됩니다. 경기 설정 변경 시 모두의 준비가, 외형 변경 시 본인의 준비가 해제됩니다. 재접속 후에도 다시 준비합니다.
- 캐릭터 선택창은 이모지 대신 **실제 3D 모델 30종과 선택 색상**을 보여줍니다.
- 혼자 입장해 연습할 수도 있습니다. 경기 중 새 참가자는 대기실에 돌아올 때까지 입장할 수 없습니다.
- 방장이 나가면 다른 참가자에게 방장 권한이 넘어갑니다. 새로고침과 짧은 연결 끊김은 20초 이내 같은 자리에 복구됩니다.

## 디자인

사용자가 선택한 **B 캠프 젤리**를 실제 홈·대기실·입장/캐릭터 모달·HUD·결과 화면과 12개 맵에 적용했습니다. 숲색·흙빛·목재 단면·나무 장식, 낮춘 조명과 노출, 무광의 흰 캐릭터와 진한 발판 경계선을 사용합니다. 캐릭터의 8가지 선택 색상은 그대로 제공합니다.

[디자인 비교실](http://localhost:3000/design-review.html?theme=forest)은 별도 참고 데모로 유지합니다. 최신 화면은 새로고침하면 반영됩니다. 서버 규칙이 함께 바뀌는 업데이트는 서버 재시작과 새 방 생성이 필요합니다.

## 조작

| 기기 | 이동 | 점프 | 다이빙 |
| --- | --- | --- | --- |
| PC | WASD 또는 방향키 | Space | Shift |
| 모바일·태블릿 | 왼쪽 가상 조이스틱 | 오른쪽 점프 | 오른쪽 다이빙 |

바닥 아래로 떨어지면 마지막으로 통과한 깃발 체크포인트에서 다시 시작합니다. 점프는 키를 놓았다 다시 눌러야 합니다. 모든 캐릭터의 능력치는 같습니다. 플레이어끼리 몸으로 길을 막고 밀 수 있고, 달려온 속도가 빠르거나 다이빙하면 충격이 더 큽니다. 충분히 높이 점프하면 머리 위로 지나갈 수 있으며, 체크포인트 복귀 직후에는 잠깐 몸싸움 보호를 받습니다.

- **점프 보정**: 발판을 벗어난 뒤 약 100ms까지 점프할 수 있고, 착지 120ms 전의 입력도 착지 후 실행합니다. 짧은 키·터치 입력이 서버 틱 사이에서 사라지지 않도록 보관하며 이단 점프와 누르고 있기 자동 점프는 허용하지 않습니다.
- **효과음**: 점프·착지·다이빙·충돌·체크포인트·완주·출발 소리를 Web Audio로 합성합니다. 홈과 경기 화면의 소리 버튼으로 끄고 켤 수 있으며 선택이 저장됩니다.
- **코스 안내**: 출발 전 3초간 코스를 살펴보고 3초 카운트다운 후 출발합니다. 동작 줄이기 설정에서는 안내 카메라를 고정합니다.
- **발판 경고**: 사라지기 전 1초 동안 주황색 안내판과 줄어드는 막대가 나타납니다. 경고와 실제 사라짐은 같은 시간 계산을 사용합니다.
- **이름표**: 짙은 배경과 굵고 밝은 글씨로 확대했습니다. 내 이름과 관전 대상은 더 크게 표시하고, 너무 먼 상대의 이름은 숨깁니다.

## 경기 모드와 결과 발표

- **단판 레이스**: 한 판의 완주 순위로 승부합니다.
- **완주 후 관전**: 달리는 친구를 자동으로 따라갑니다. 이름 선택·이전/다음·내 캐릭터 보기로 전환하며, 대상이 완주하거나 연결이 끊기면 다음 참가자를 보여줍니다.
- **누적 점수전**: 방장이 선택한 3·5·7판의 점수를 합산합니다. 한 판의 참가 인원이 N명이면 1위 N점, 2위 N−1점, 이후 1점씩 감소하며 미완주는 0점입니다. 예를 들어 30명 경기의 1위는 30점, 30위는 1점입니다. 최종 동점은 공동 순위입니다.
- 각 판이 끝나면 방장이 **다음 라운드 시작**을 누릅니다. 마지막 판 뒤에는 누적 점수로 최종 순위를 공개합니다. 경기 중 참가자가 떠나도 이미 얻은 점수는 최종 결과에 남습니다.
- **결과 카드**: 실제 게임 캐릭터와 색상을 촬영한 정사각형 사진·이름 카드를 격자로 배열합니다. 미완주와 낮은 순위부터 한 장씩 뒤집히고 1위를 마지막에 공개합니다. 점수전에서는 획득·누적 점수, 마지막에는 최종 총점을 표시합니다.
- **모두 공개**로 연출을 건너뛸 수 있습니다. 시스템의 동작 줄이기 설정도 따릅니다.

## 12개의 코스

모든 맵의 마지막 구간에는 **점프 없이 달릴 수 있는 넓은 우회로**와 **좁은 발판·틈새를 넘어 빠르게 갈 수 있는 지름길**이 있습니다. 갈림길 앞에 체크포인트가 있으며, 지름길의 틈새는 맵 난이도에 따라 3~4m입니다.

| 맵 | 주요 장애물·기믹 |
| --- | --- |
| 젤리 정원 | 범퍼, 회전봉, 지그재그 벽 |
| 빙글빙글 시티 | 속도·방향이 다른 연속 회전봉 |
| 구름 징검다리 | 떨어진 발판, 점프 패드 |
| 아이스 익스프레스 | 미끄러운 얼음, 움직이는 범퍼 |
| 네온 팩토리 | 컨베이어 벨트, 압축 게이트 |
| 바람 골짜기 | 양방향 돌풍, 좁은 길 |
| 문 열려라 축제 | 서로 다른 주기로 열리는 문 |
| 진자 항구 | 길을 가로지르는 대형 진자 |
| 반짝 사라진 길 | 사라지는 발판, 타이밍 점프 |
| 캔디 계단 | 높이 차이가 있는 계단, 얼음 |
| 핀볼 파크 | 범퍼 미로, 점프 패드 |
| 왕관 대소동 | 얼음·돌풍·회전봉·발판·진자 종합 |

## 다른 기기에서 접속하기

### 같은 Wi-Fi·교실 네트워크

1. 서버 PC에서 `ipconfig`로 해당 네트워크의 IPv4 주소를 확인합니다.
2. 예를 들어 PC 주소가 `192.168.0.20`이면 **방장도** `http://192.168.0.20:3000`으로 접속해 방을 만듭니다.
3. 그 화면에서 초대 링크를 복사하면 친구도 같은 주소로 들어옵니다.
4. Windows 방화벽에서 Node.js의 해당 네트워크 접근이 허용되어야 합니다. 학교 Wi-Fi의 기기 간 통신 제한이 있으면 네트워크 관리자 설정이 필요합니다.

`localhost`는 접속한 기기 자신을 뜻하므로, `localhost` 초대 링크는 다른 기기로 전달해도 서버 PC에 연결되지 않습니다.

### 인터넷 공개 서버

**Render 배포 완료**: [camp-jelly.onrender.com](https://camp-jelly.onrender.com/). 이 주소에서 방을 만든 뒤 초대 링크를 보내면 다른 네트워크의 친구도 이름 입력 후 참가할 수 있습니다. HTTPS와 보안 WebSocket(WSS)을 사용합니다.

| 배포 설정 | 값 |
| --- | --- |
| 프로젝트 / 환경 | fallguys / 극기훈련 |
| 서비스 | camp-jelly · Web Service · Free · Singapore |
| 연결 저장소 / 브랜치 | kimmokdong/fallguys · 비공개 · main |
| 런타임 | Node.js 24 · `.node-version` |
| 빌드 명령 | `npm ci --omit=dev && npm test` |
| 시작 명령 / 헬스 체크 | `npm start` / `/` |
| 자동 배포 | main에 push하면 설치·테스트 후 재배포 |

[Render 서비스 관리](https://dashboard.render.com/web/srv-dafpdhn40ujc73cb4pi0)에서 배포 로그와 설정을 확인합니다. 코드를 수정한 후 Git에 커밋하고 `git push`하면 반영됩니다. 외부 데이터베이스 없이 단일 프로세스 메모리로 방을 유지하므로 **재배포·서버 재시작 시 진행 중인 방과 결과는 초기화됩니다**. 경기가 없는 시간에 업데이트하세요.

무료 서비스는 요청이 없는 상태가 15분 지속되면 절전 상태가 되고, 다음 접속의 시작에 약 1분이 걸릴 수 있습니다. 무료 사용 시간·전송량 등 제한은 [Render 무료 서비스 안내](https://render.com/docs/free)를 따릅니다.

다른 Node.js 호스팅으로 옮길 때의 설정은 다음과 같습니다.

- 저장소 전체와 `package-lock.json`을 업로드합니다.
- 설치 명령: `npm ci --omit=dev`
- 실행 명령: `npm start`
- 환경 변수: 호스팅 서비스가 제공하는 `PORT`를 자동으로 사용합니다. 기본값은 `3000`, 바인딩은 `0.0.0.0`입니다.
- HTTPS 도메인으로 접속하면 클라이언트는 자동으로 `wss://`에 연결합니다. 리버스 프록시는 WebSocket Upgrade를 허용해야 합니다.
- 정적 파일만 배포하는 서비스는 방 서버를 실행할 수 없습니다.
- `Dockerfile`로 컨테이너 배포도 가능합니다. 단일 인스턴스로 실행하세요. 서버 재시작 시 메모리의 방·결과는 사라집니다.

```powershell
docker build -t jelly-rush .
docker run --rm -p 3000:3000 jelly-rush
```

## 핵심 기술과 구조

| 파일 | 역할 |
| --- | --- |
| `server.js` | HTTP·WebSocket 서버, 방장 권한, 방·재접속·경기 결과 관리 |
| `public/world.js` | 12개 코스, 서버 물리·충돌, 점프·다이브·체크포인트 |
| `public/scene.js` | Three.js 3D 캐릭터·코스·카메라·프레임 보간 |
| `public/catalog.js` | 캐릭터 30종과 색상 8종 |
| `public/app.js` | 초대·대기실·설정·모바일 조작·순위 UI |
| `public/results.js` | 점수 합산·공동 순위·카드 공개 순서와 시간 |
| `public/audio.js` | 사용자 입력 후 시작하는 효과음 합성·음소거 |
| `public/style.css` | 반응형 화면과 게임 HUD |

프런트엔드는 Vanilla JavaScript·CSS, 서버는 Node.js 내장 HTTP와 `ws`, 그래픽은 Three.js를 사용합니다. 서버가 초당 30회 이동·충돌을 계산하고 초당 15회 상태를 전송합니다. 클라이언트가 보내는 위치나 완주 주장은 사용하지 않습니다. 게임 에셋은 코드로 생성해 별도 이미지·모델 다운로드가 필요하지 않습니다. Google Fonts 연결이 없으면 시스템 글꼴을 사용합니다.

## 검증

```powershell
npm test
```

Node.js 기본 테스트 러너로 최대 30명 WebSocket 입장, 31번째 거부, 방장 권한, 랜덤 배정, 재접속과 세션 교체, 중도 탈퇴, 결과 순위, 잘못된 입력·파일 경계, 12개 코스의 시작·체크포인트·완주 및 물리 동작을 확인합니다. 플레이어 충돌·밀기·다이빙·벽 관통 방지, 30명 겹침의 안정성, 실제 WebSocket 충돌 전송, 3판 누적·역전·동점·맵 중복 방지와 결과 공개 순서까지 검증합니다.

별도 테스트 서버의 30명 결과 데이터로 실제 3D 사진 30개, 낮은 순위부터 공개되는 연출, 3판 합산 최종 결과와 390px 모바일 결과 화면도 확인했습니다.

최신 자동 테스트 **17개 통과**. 준비 권한·설정/외형 변경·재접속 초기화, 짧은 WebSocket 점프 입력, 점프 유예·예약·이단 점프 방지, 발판 경고 시점, 12개 맵의 양쪽 경로 실제 완주와 지름길의 시간 단축을 포함합니다. 브라우저에서는 준비 후 시작·열린 캐릭터 창의 옵션 동기화·30명 이름표와 관전 대상 교체·음소거 저장·다음 라운드 초기화·모바일 결과를 확인했습니다.

독립 Chrome 브라우저 2개에서 초대 링크 → 이름 입력 → 대기실 → 경기 동기화를 확인했습니다. 실제 키보드 이동·점프와 초기 코스 완주, 390px 모바일 화면, 캐릭터 변경 및 브라우저 오류·경고 0건을 확인했습니다.

Render 배포 시에도 자동 테스트 17개를 통과했습니다. 공개 HTTPS/WSS 주소에서 30개 동시 연결, 랜덤 캐릭터 30종, 정원 초과 거부, 준비 후 시작, 점프와 모든 참가자의 경기 상태 수신을 검증하고 임시 방을 정리했습니다. 실제 다른 기기 30대를 동원한 장시간 성능 테스트는 아직 수행하지 않았습니다.
